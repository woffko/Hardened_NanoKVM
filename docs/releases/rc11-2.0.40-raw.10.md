# Hardened NanoKVM 2.0.40 RC11 + System 0.3.0 Raw 10

This is one combined release containing the application update, signed raw
system update, and manually flashable SD-card image.

## Important Upgrade Order

**Existing NanoKVM installations must update the application to `2.0.40`
before starting the raw system update.**

1. Install the `2.0.40` application update and wait for the backend to restart.
2. Confirm that the Application version page reports `2.0.40`.
3. Only then enable raw system updates and install `0.3.0-raw.10`.

The raw updater is implemented by the application backend. Updating the app
first ensures that hostname, web/SSH credentials, HTTPS configuration, SSH host
keys, network settings, remote syslog, Tailscale/PicoClaw state, and other
preserved configuration are handled by the corrected updater.

For a clean manual SD-card flash, no separate app update is needed: the SD image
already contains app `2.0.40`.

## Application 2.0.40 RC11

- Keeps an H.264 Direct WebSocket alive while another client temporarily
  selects MJPEG, then resumes H.264 on the same socket without requiring a
  WebRTC switch or reconnect.
- Completes process-level MMF/VB/VENC teardown so a backend restart after active
  MJPEG/H.264 capture does not leave the vendor encoder stack initialized.
- Preserves generated remote-syslog defaults across raw partition updates.
- Makes static DNS rendering atomic and idempotent instead of accumulating
  duplicate nameservers after repeated starts.
- Carries the complete native C/C++ hardening baseline: camera/thread lifetime,
  VENC buffer ownership and rollback, bounds and stride fixes, I2C failure
  handling, allocation checks, and retained helper synchronization fixes.
- Updates the Rust/web dependency graph; 154 Rust tests, the production web
  build, RustSec audit, and production pnpm audit pass.

**Recommendation:** after updating the app to `2.0.40`, users with verified
recovery media are encouraged to try the new Buildroot `2026.05.1` system from
this same release and report hardware compatibility.

## System 0.3.0-raw.10

- Replaces the legacy Buildroot `2023.11.2` userspace with a tracked external
  board port based on Buildroot `2026.05.1`.
- Includes app `2.0.40`, the Rust-only backend, web assets, native libraries,
  `kvm_system`, and hardened init/update behavior.
- Uses OpenSSH, current Buildroot userspace packages and CA certificates while
  excluding unused Python and FFmpeg runtimes from the target image.
- Includes the hardware-accepted source-built `soph_vcodec`, `soph_jpeg`, and
  `soph_vc_driver` media-module replacements.
- Preserves HTTPS, SSH identity, hostname, credentials, manual network/DNS,
  remote syslog, and supported persistent service state across raw update.
- Retains the proven vendor kernel `5.10.4-tag-`; this release is a userspace
  migration, not the future Linux `5.10.265` security merge.

## Validation

- Signed raw update installed on NanoKVM Cube `10.0.87.133` through the normal
  system-update API.
- Same-WebSocket H.264 regression passed without reconnecting.
- Complete core/network/syslog/native/browser/video/USB/peripheral/watchdog
  suite passed.
- Five reboot cycles passed with exact backend, native-library, module, helper,
  DNS, UDC, and boot-good invariants.
- Thirty-minute endurance passed across 37 MJPEG/H.264 cycles with 5,510 MJPEG
  frames, 22,752 H.264 packets, and zero new dmesg/local-syslog alerts.
- A SanDisk High Endurance card booted the manually flashable image successfully
  and obtained network configuration from the router.

## Recovery And Known Limits

- Raw updates overwrite `/dev/mmcblk0p1` and `/dev/mmcblk0p2` and do not provide
  automatic partition rollback. Keep a working SD card or full recovery image.
- Do not interrupt the raw write or the first boot. A fresh card expands rootfs
  to about 8 GiB and creates the `/data` partition on remaining space; use a
  card of at least 16 GiB.
- The vendor kernel remains `5.10.4-tag-`. A reconstructed `5.10.265` merge is
  not included and must pass recoverable-media testing separately.
- Visible mouse, host BIOS/UEFI, OLED/button, separately authorized ATX, and
  controlled power-loss coverage remain hardware follow-up gates.
- Several retained vendor firmware/runtime inputs have `NOASSERTION` or
  proprietary licensing metadata. Redistribution and commercial-use rights
  require a separate review; this candidate is published for experimental
  compatibility testing only.
