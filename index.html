What Changed

Hardened NanoKVM keeps the upstream hardware stack and focuses on backend, update, and administration hardening.

Rust-only web backend

Release packages ship the Hardened Rust server, keep only the required native helpers, and reject legacy backend switch files in shipped artifacts.

Hardened authentication

First-boot account setup, CSRF binding, Origin checks, session revocation, login lockout, Argon2id passwords, security headers, and no in-place password reset path.

Signed updates

Application and system channels use signed metadata, archive verification, guarded installs, and explicit separation between app and raw system updates. RC11 combines both artifacts while preserving the required app-first order.

Mobile view

Hardened adds a phone and touch-tablet view that was not present in the original NanoKVM project: mobile settings navigation, reachable submenus, native mobile keyboard controls, TouchSync, pinch-to-zoom, panning, and forced Mobile view.

System controls

GUI pages for time/NTP, system logs, remote syslog, firewall modes, and network settings under Settings > System.

Managed firewall modes

Moderate is the default local-use profile. Restricted and Paranoid also accept new inbound connections only from private, ULA, link-local, or loopback source ranges.

Video path stability

H.264 Direct remains the preferred low-CPU path. RC11 resumes H.264 on the same WebSocket after a temporary MJPEG selection and completes native encoder teardown during backend restarts.

Buildroot 2026 preview

The optional raw/SD preview moves userspace from Buildroot 2023.11.2 to 2026.05.1 while deliberately retaining the accepted vendor kernel 5.10.4-tag- and boot boundary.

Update Model

Two update paths exist because replacing kvmapp is much safer than writing raw SD-card partitions.

Application updates

Replace the Rust server, web assets, helper scripts, init scripts, keys, version files, and kvmapp-side defaults.

Raw system updates

Write boot and rootfs partition images to the SD card. These updates can change the base system and require guarded recovery assumptions.

Offline recovery

Keep physical SD-card recovery access. Raw partition updates have no automatic rollback if the device cannot boot.

Hardened NanoKVM is beta/lab firmware. Read the release notes before installing, keep the original SD card or a known-good backup, and do not enable raw system updates without physical recovery access. RC11 passed the complete automated device suite, same-WebSocket H.264 regression, five reboot cycles, 30-minute stream/log endurance, and a SanDisk High Endurance recovery-card boot. Visible mouse, host BIOS/reboot, OLED/button, separately authorized ATX, and controlled power-loss coverage remain follow-up limits. Some retained vendor components have NOASSERTION licensing metadata; see the release notes and vendor-input manifest.
Hardened NanoKVM is an independent security-focused fork for Sipeed NanoKVM. NanoKVM hardware documentation remains available from Sipeed.
